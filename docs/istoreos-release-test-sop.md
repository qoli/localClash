# iStoreOS 測試 SOP

以 [功能測試表](istoreos-test-features.md)選測並保存最後實測結果。
代理執行方式由 [測試 skill](../.codex/skills/localclash-istoreos-test/SKILL.md)維護。

## 執行

1. 比較候選與基準的變更，選受影響功能及必要交互回歸。需要沿用歷史證據時，核對原實測版本至候選的累積差異；發版不等於全表重測。
2. 記錄候選版本／SHA、實際核心及所需環境。功能交互使用授權的可拋棄 iStoreOS QEMU；[VM 腳本](../scripts/istoreos-test-env.sh)只管理 VM，其他 fixture 按需準備。
3. 從正式入口操作，核對任務終態、保存／載入及使用者可觀察結果。UI 驗證走 UI，單元測試或 RPC 成功不能替代所選交互。
4. 保留首次失敗及原始證據。在授權範圍內修復並重走失敗流程；環境問題只影響真正依賴它的測試，獨立項繼續。
5. 回寫功能表的實測版本、覆蓋及證據，彙整本輪結果、修復回驗與剩餘風險。沿用及未執行項保留原實測版本。

## 結果與發布

產品斷言記 PASS／FAIL；環境或工具問題記 ERROR，未執行記 NOT_RUN 並說明原因。
部分操作通過只記該範圍，新的失敗不能被舊 PASS 隱藏。原始證據保留於本機
`.runtime/istoreos-acceptance/<run-id>/`；版控只記脫敏摘要與證據索引。

發布摘要（沿用 G99 名稱）說明已測內容、缺陷／修復／回驗、未覆蓋範圍及風險。
功能表空欄或無關環境錯誤不自動阻擋發布；公開發布仍依使用者授權。
CI 的源碼、建置與資產檢查不替代 QEMU 交互證據；公開產物須核對受測內容與 SHA。
